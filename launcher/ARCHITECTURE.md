# Архитектура и дорожная карта: Lowuncher

## 1. Сводка согласованного технологического стека

| Компонент | Технологическое решение | Обоснование |
|---|---|---|
| **Язык** | Python 3.11+ | Быстрая разработка, богатая экосистема |
| **Графический интерфейс** | PySide6 (Qt) | Стабильность, поддержка фоновых потоков `QThread`, современная QSS-стилизация |
| **Библиотека запуска** | `minecraft-launcher-lib` | Официальные алгоритмы генерации аргументов JVM, скачивания библиотек и ассетов Mojang |
| **Версия игры и загрузчик** | Minecraft 1.21.1 + NeoForge | Актуальная версия с отличной оптимизацией модов |
| **Управление Java** | Автоскачивание Adoptium Temurin JRE 21 | Полная изоляция в `~/.lowuncher/runtime/java-21/`, ноль проблем с системной Java у игроков |
| **Хранилище модов и манифеста** | GitHub Releases (бесплатно, без лимитов трафика) | Прямые ссылки `latest/download/...`, отсутствие кэширования Raw Git |
| **Синхронизация модов** | Пофайловая сверка SHA-256 через `manifest.json` | Игроки докачивают только новые/обновлённые моды за пару секунд |
| **Авторизация** | Двойной вход (Оффлайн по нику + Microsoft OAuth2) | Поддержка любых игроков + предпросмотр скина через API |
| **Изоляция директории** | `%APPDATA%/.lowuncher` (Win) / `~/.lowuncher` (Linux) | Никаких пересечений с TLauncher/Prism или личным `.minecraft` |
| **Сборка дистрибутива** | Портативный `.exe` через PyInstaller + автопроверка апдейтов | Один файл для скачивания школьниками |

## 2. Структура репозитория

```text
lowuncher/
├── core/                       # Ядро лаунчера (чистая логика без UI)
│   ├── __init__.py
│   ├── config.py              # Чтение/запись настроек (launcher_config.json)
│   ├── java_manager.py        # Проверка и авто-скачивание Java 21 (Adoptium)
│   ├── installer.py           # Скачивание ванильного MC 1.21.1 и установка NeoForge
│   ├── sync_engine.py         # Загрузка manifest.json, сверка SHA-256, скачивание модов
│   ├── auth.py                # Оффлайн-профиль (UUID) + Microsoft OAuth2
│   ├── launcher.py            # Сборка аргументов и запуск процесса Minecraft
│   └── server_ping.py         # Проверка онлайна игрового сервера (ping)
│
├── ui/                         # Пользовательский интерфейс PySide6
│   ├── __init__.py
│   ├── main_window.py         # Главный экран (аватар, ник, кнопка "Играть", прогресс)
│   ├── settings_dialog.py     # Модальное окно настроек (RAM, папка, логи)
│   ├── log_viewer.py          # Окно логов (появляется при сбоях игры)
│   ├── worker_threads.py      # QThread фоновые задачи (скачивание/запуск без фризов UI)
│   └── styles/
│       ├── dark_theme.qss     # Современный тёмный стиль UI
│       └── assets/            # Иконки, логотипы, дефолтный скин
│
├── tools/                      # Утилиты для создателя сборки (администратора)
│   └── generate_manifest.py   # CLI-скрипт: сканирует папку mods/ и генерирует manifest.json
│
├── build/                      # Скрипты сборки
│   └── build_exe.py           # Автоматизация сборки через PyInstaller в один .exe
│
├── main.py                     # Точка входа в приложение
├── requirements.txt            # Зависимости Python
└── README.md                   # Инструкция по сборке и обновлению сборок
```

## 3. Схема данных манифеста (`manifest.json`)

Манифест хранится в GitHub Releases и содержит полную информацию о необходимом состоянии клиента:

```json
{
  "launcher_version": "1.0.0",
  "minecraft_version": "1.21.1",
  "loader": {
    "type": "neoforge",
    "version": "21.1.72"
  },
  "java_version": 21,
  "files": [
    {
      "path": "mods/jei-1.21.1-neoforge.jar",
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "size": 1048576,
      "url": "https://github.com/your-org/modpack/releases/download/v1.0.0/jei-1.21.1-neoforge.jar",
      "required": true
    },
    {
      "path": "config/defaultoptions.txt",
      "sha256": "4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a",
      "size": 2048,
      "url": "https://github.com/your-org/modpack/releases/download/v1.0.0/defaultoptions.txt",
      "required": false,
      "overwrite": false
    }
  ]
}
```

> **Важное свойство `overwrite: false`**: для конфигов и опций игрока лаунчер не перезаписывает файл, если он уже существует локально, сохраняя персональные настройки графики и биндов.

## 4. Поэтапный план разработки (Roadmap)

### Этап 1: Базовое ядро запуска (Core Engine)
- Реализация `java_manager.py`: определение ОС, скачивание и распаковка портативной Adoptium Java 21 при её отсутствии.
- Реализация `installer.py`: установка базового Minecraft 1.21.1 и интеграция загрузчика NeoForge.
- Реализация `launcher.py`: сбор параметров JVM, аргументов запуска и запуск процесса с оффлайн-опциями.

### Этап 2: Синхронизация и генератор манифеста (Sync Engine)
- Реализация скрипта `tools/generate_manifest.py` для админа (автоматическое хэширование файлов модов).
- Реализация `sync_engine.py`: фоновая загрузка `manifest.json`, сверка контрольных сумм локальных файлов, удаление устаревших `.jar` и скачивание новых с подсчётом общего прогресса.

### Этап 3: Графический интерфейс на PySide6 (UI)
- Главный экран со стилизацией: логотип, индикатор статуса сервера, поле ника, кнопка «ИГРАТЬ», плавный прогресс-бар.
- Интеграция фонового потока `QThread` (`worker_threads.py`): передача стадий («Проверка Java», «Синхронизация модов 4/12», «Запуск игры...») в UI без зависаний интерфейса.
- Диалог настроек (выделение RAM, кнопка «Открыть папку с игрой»).

### Этап 4: Аватары, SkinRestorer и отладка
- Получение превью скина по никнейму игрока (голова/аватар) через внешний API для отображения в UI.
- Отлов завершения процесса Minecraft: если код выхода ненулевой (краш игры), лаунчер автоматически показывает окно с логом для быстрой помощи игроку.
- Пинг игрового сервера (отображение онлайна).

### Этап 5: Сборка и дистрибуция
- Подготовка скрипта `build_exe.py` с PyInstaller: вшивание иконки, исключение лишних библиотек для оптимизации размера.
- Автоматическая проверка обновлений самого лаунчера через GitHub Releases при старте.
- Инструкция для игроков и для администратора сборки.
